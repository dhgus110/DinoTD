# 판매·약탈·방어 기획서

> 문서 상태: 검토 중
>
> 담당 범위: 공방 상품의 판매대 인계, 손님·상품 요청 말풍선, 계산대·계산 창구와 코인 운반,
> 약탈 경보·손님 대피·창구 셔터, 벽·출입문·방어 동료·치료소, 온라인·오프라인 결과
>
> 규칙 원본: 이 문서는 판매와 기지 방어 흐름의 단일 원본이다.
>
> 상위 규칙: [`core-gameplay.md`](core-gameplay.md)의 계산대·약탈·치료 확정 규칙을 따른다.
>
> 수치 원본: 비용·시간·확률·손실률·수용량은 [`progression-balance.md`](progression-balance.md)에서 관리한다.

## 1. 목적과 범위

### 1.1 플레이어 가치

플레이어는 공방에서 만든 상품이 판매대에 진열되고, 손님이 요청한 상품을 계산 창구에서 구매한 뒤,
코인이 실제로 메인 기지까지 운반되는 과정을 확인한다. 판매대와 계산대에 쌓인 아직 안전하지 않은
가치는 약탈 위험을 만들며, 방어 동료·벽·출입문·치료소를 준비할 이유가 된다.

### 1.2 포함 범위

- 판매대 재고, 손님 대기 줄, 상품 요청 말풍선과 상품 품절 대기
- 계산대와 1~5개 계산 창구의 응대 순서, 판매 완료와 코인 생성
- 플레이어 직접 코인 운반, 계산대 전용 일꾼 운반, 입고·약탈 경계
- 약탈 무리의 발생 조건, 약탈 경보, 손님 대피, 창구 셔터 폐쇄·개방
- 벽·출입문과 방어 야영지, 온라인 직접 방어·자동 방어의 결과
- 벽 손상·수리, 상품·코인 손실, 직접 방어의 영입·재화 선택
- 방어 동료의 부상, 치료 대기열, 온라인·오프라인 치료와 자동 복귀
- 판매·방어의 화면 피드백, 시각·사운드·상황별 확인 사례

### 1.3 제외 범위

- 상품의 재료·생산 시간·판매가, 약탈 조건의 수치와 치료 비용은
  [`progression-balance.md`](progression-balance.md)의 단일 표를 참조한다.
- 공방 생산, 파견, 메인 기지 공간과 비콘의 상세는 [`base-automation.md`](base-automation.md)를 따른다.
- 생물 종별 이름·외형·전투 수치와 공격 계산은 콘텐츠 범위다.
- 코드, 자료형·데이터 컬럼, 저장 구조, 분석 이벤트, 처리 알고리즘과 기술 성능 기준은 다루지 않는다.

## 2. 상태와 결정 순서

### 2.1 결정 상태

- **확정**: 계산대가 통합 시설이고 계산 창구가 손님 한 명을 응대하며, 창구 셔터와 벽·출입문이
  서로 다른 역할을 가진다는 코어 규칙이다.
- **가정**: 직접 방어 모드의 진입 시점, 손님의 대기 상태 표현, 약탈 결과 화면의 표시 순서는 출시 흐름을
  만들기 위해 정했다.
- **검증 필요**: 손님 대피와 복귀가 전투 화면을 가리지 않는지, 약탈 손실이 방어 선택을 만들면서도
  반복 판매를 막지 않는지 확인한다.
- **미정 없음**: 출시 판매·방어 흐름에는 각 정상·부족·중단·실패 상황의 결과가 있다.

### 2.2 결정 순서

1. 판매 가능한 상품 재고가 판매대에 도착했는지 확인한다.
2. 손님 요청을 정하고 줄 순서와 대기 시간을 시작한다.
3. 빈 계산 창구를 선두 손님에게 배정하고 상품을 소비해 코인을 만든다.
4. 코인이 계산대 또는 운반 중인지, 메인 기지에 입고됐는지 구분한다.
5. 방어 시설 완성·안전하지 않은 가치·최소 간격을 확인해 약탈 경보를 결정한다.
6. 손님을 대피시키고 셔터를 닫은 뒤 방어 결과와 손실을 처리한다.
7. 벽·출입문 손상, 동료 부상·치료, 계산대 재개와 손님 복귀를 표시한다.

약탈 경보가 판매 완료와 동시에 발생하면 해당 판매를 먼저 완료하고 생성된 코인을 안전하지 않은
계산대 코인으로 포함한다. 그 다음 손님 합류·판매를 멈추고 대피를 시작한다.

## 3. 판매대와 손님

### 3.1 판매대 재고

- 공방에서 완성된 상품이 판매대에 도착한 순간부터 손님이 구매할 수 있는 재고가 된다.
- 판매대는 공방과 계산대 사이의 상품 보관 공간이며, 안전 자원 보관소가 아니다.
- 판매대 재고의 판매가 합계는 약탈 경보 조건에 포함된다. 메인 기지에 입고된 돌·나무·뼈와 소울은
  상품 재고와 합산하지 않는다.
- 상품이 하나도 없으면 새 손님을 줄에 넣지 않는다. 이미 줄에 있는 손님은 상품 요청 말풍선을
  유지하며 기다리거나 최대 대기 시간이 끝나면 떠난다.
- 공방에서 상품이 추가되면 대기 중 손님의 요청을 먼저 확인한다. 요청 상품이 재입고되면 줄 순서를
  바꾸지 않고 선두부터 구매를 진행한다.

### 3.2 손님 진입과 요청

- 손님은 기지 남쪽, 계산대 정면의 대기 구역에 한 줄로 선다. 벽·출입문이 완성된 뒤에도 대기 구역은
  남쪽 벽 바깥에 남는다.
- 줄에 들어오는 순간 판매대에서 현재 재고가 있는 상품 종류 하나를 요청으로 선택한다.
- 손님 머리 위에 상품 요청 말풍선을 표시하고, 말풍선에는 상품 아이콘을 넣는다.
- 상품 종류가 하나면 그 상품을 요청한다. 둘 이상이면 판매 가능한 종류 목록 중 하나를 균등하게
  선택한다. 선택 뒤에는 재고가 바뀌어도 요청을 다시 뽑지 않는다.
- 손님이 구매를 완료하거나 줄에서 떠나면 해당 말풍선을 제거한다.
- 줄 상한과 손님 도착 간격·최대 대기 시간은 [`progression-balance.md`](progression-balance.md#43-공방과-판매)를
  참조한다. 상한에 도달하면 새 손님을 추가하지 않고, 현재 줄은 순서를 유지한다.

### 3.3 정상·예외 흐름

1. 판매대에 재고가 생긴다.
2. 줄에 빈자리가 있고 약탈 경보가 없으면 손님이 들어온다.
3. 손님은 요청을 선택하고 말풍선을 띄운다.
4. 빈 계산 창구가 생기면 줄 선두 손님부터 이동한다.
5. 요청 상품 1개를 재고에서 차감하고 판매가만큼 코인을 계산대에 만든다.
6. 손님이 계산대 정면을 떠나고 다음 손님이 배정된다.

- 요청 상품이 품절되면 손님은 창구에 들어가지 않고 줄에서 기다린다. 다른 상품 재고가 생겨도
  요청을 바꾸지 않는다.
- 최대 대기 시간이 끝나면 손님은 상품을 받지 못한 채 떠나며 재고·코인을 바꾸지 않는다.
- 약탈 경보가 시작되면 새 손님 진입과 판매 진행을 즉시 멈춘다. 상품 1개 차감과 코인 생성은 한 덩어리로
  처리한다. 경보가 처리되기 전에 판매가 시작되면 두 결과를 함께 완료하고, 그 뒤에 멈춘다. 아직 판매가
  시작되지 않았으면 상품과 코인을 바꾸지 않은 채 기존 요청을 유지하고 대피한다.

## 4. 계산대와 계산 창구

### 4.1 시설 구분

- 계산대는 통합 시설 하나이며 판매대의 상품 재고와 모든 계산 창구의 코인을 공유한다.
- 계산 창구는 손님 한 명을 응대하는 자리다. 한 창구에는 한 번에 한 명만 들어간다.
- 메인 기지의 큰 단계가 바뀌면 운영 창구 수를 즉시 늘린다. 실제 1~5개 수치는
  [`progression-balance.md`](progression-balance.md#51-메인-기지-단계-비용)만 참조한다.
- 다섯 창구의 자리와 양옆 벽 연결부는 게임 시작부터 예약한다. 창구가 늘어나도 계산대를 옮기지
  않는다.
- 계산대 정면은 남쪽 대기 구역과 이어지고, 안쪽은 메인 기지 물류 공간과 이어진다.

### 4.2 배정과 판매 우선순위

1. 약탈 경보가 없고 사용 가능한 창구가 있는지 확인한다.
2. 줄 선두 손님부터 가장 가까운 빈 창구로 이동시킨다.
3. 여러 창구가 비어 있으면 줄 앞 순서를 먼저 적용하고, 창구 위치는 보조 기준으로 사용한다.
4. 상품 요청이 재고에 없으면 해당 손님을 창구에 배정하지 않고 다음 손님으로 건너뛰지 않는다.
   선두 손님이 기다리는 동안 뒤 손님은 선두가 요청한 상품과 다른 재고를 가지고 있어도 창구를
   선점하지 않는다.
5. 판매가 완료되면 재고 1개를 소비하고 코인을 계산대에 쌓는다.

이 우선순위는 여러 창구가 동시에 비어도 한 줄의 순서를 보존한다. 창구가 모두 사용 중이면 줄은
계속 유지되고, 손님별 대기 시간이 흐른다.

### 4.3 판매 중단과 재개

- 창구 셔터가 닫히는 순간 새로운 손님과 판매를 중단한다.
- 셔터가 닫혀 있는 동안 공방 생산, 판매대 재고 이동, 계산대 내부·메인 기지 사이의 코인 운반은
  계속한다.
- 약탈 무리가 퇴각하면 벽·출입문 파괴 여부와 관계없이 셔터를 모두 열고 판매를 재개한다.
- 대피한 손님은 기존 줄 순서와 요청을 유지한다. 남은 대기 시간은 대피 중에는 멈추고, 복귀 뒤
  다시 흐른다.
- 복귀한 손님의 요청 상품이 약탈로 줄었다면 말풍선을 복원한 채 재입고를 기다린다.

## 5. 계산대 코인 운반

### 5.1 시작 상태

- 판매 완료 코인은 계산대에 쌓이고, 메인 기지에 도착하기 전까지 안전 자원이 아니다.
- 계산대 1단계에서는 플레이어가 계산대에 접근해 코인을 직접 들고 메인 기지 입고 범위까지 운반한다.
- 플레이어가 코인을 들고 있는 동안은 돌·나무·뼈 등짐과 별도 운반 상태로 처리한다. 코인 운반량은
  현재 플레이어 운반력까지이며, 운반력 수치는 [`progression-balance.md`](progression-balance.md#41-플레이어-현장-채집과-생물-결과)를
  참조한다.
- 플레이어가 코인을 내려놓거나 입고 범위에 들어오기 전까지 코인은 약탈 대상이다.

### 5.2 전용 일꾼

- 계산대 첫 강화가 완료되면 계산대 전용 일꾼 자리 1개를 공개한다.
- 일꾼을 그 자리에 배치하면 계산대의 코인을 자신의 운반력까지 싣고 메인 기지로 실제 운반한다.
- 일꾼은 계산대에 쌓인 코인이 자신의 운반량보다 적어도 가능한 양을 싣고 이동한다.
- 메인 기지 입고 범위에 도착하면 코인을 내려놓고 안전 자원으로 만든다.
- 담당 일꾼이 다른 역할로 바뀌면 손에 든 코인을 먼저 메인 기지에 내려놓은 뒤 역할을 바꾼다.
  새 코인은 플레이어 직접 운반 상태로 돌아간다.
- 코인 운반 일꾼이 약탈로 쓰러지거나 운반을 멈추면 운반 중인 코인은 안전 자원이 되지 않는다. 약탈
  결과는 계산대와 운반 중 코인을 함께 확인한다.

### 5.3 운반 중단과 재개

- 플레이어가 코인을 들고 포탈로 이동할 수 없다. 먼저 메인 기지 입고 범위에 도착해야 한다.
- 계산대와 메인 기지 사이에 코인을 옮기는 동안 약탈 경보가 발생해도 운반은 계속되며, 기지 안쪽에
  도착한 코인은 약탈 결과에서 제외한다.
- 벽·출입문이 파괴된 뒤 약탈 무리가 기지 안쪽에 도착하면 계산대와 운반 중인 코인이 모두 안전하지
  않은 코인으로 판정된다.
- 약탈 종료 뒤 남은 코인은 기존 위치에서 운반을 재개한다. 이미 잃은 코인을 다시 생성하지 않는다.

## 6. 약탈 경보·방어 결과

### 6.1 약탈 해금과 경보 조건

- 첫 상품 판매 완료 시 벽·출입문과 방어 야영지 건설 비콘을 공개한다.
- 두 시설이 모두 완성되기 전에는 약탈 무리가 발생하지 않는다.
- 두 시설이 모두 완성되면 약탈 시스템을 영구 해금한다.
- 약탈은 번호가 붙은 전투 단계가 아니라, 판매대 상품과 안전하지 않은 계산대·운반 중 코인의 가치가
  누적될 때 발생하는 기지 사건이다.
- 정확한 최소 가치·확인 간격·발생 확률·약탈 무리 규모는
  [`progression-balance.md`](progression-balance.md#45-약탈과-치료)를 따른다.
- 한 약탈이 끝난 뒤 최소 간격 동안에는 새 약탈을 추첨하지 않는다. 최소 간격이 끝난 뒤에도 안전하지
  않은 가치가 기준 아래면 발생하지 않는다.

### 6.2 약탈 경보 상태 전이

| 현재 상태 | 트리거 | 조건 | 다음 상태 | 플레이어 피드백 |
| --- | --- | --- | --- | --- |
| 판매 중 | 약탈 추첨 성공 | 두 방어 시설 완성 | 경보·대피 | 경보음, 화면 상단 경고, 새 손님 중단 |
| 경보·대피 | 남쪽 정면의 손님이 모두 빠짐 | 대피 중인 손님이 없음 | 셔터 폐쇄 | 모든 창구 셔터가 동시에 내려감 |
| 셔터 폐쇄 | 약탈 무리 도착 | 벽·출입문이 남아 있음 | 방어 중 | 방어 동료가 출입문으로 이동 |
| 방어 중 | 모든 약탈자 패배 | 벽·출입문 체력 0 아님 | 방어 성공 | 상품·코인 유지, 손님 복귀 준비 |
| 방어 중 | 벽·출입문 체력 0 | 약탈자가 기지에 들어옴 | 기지 약탈 | 벽 파괴, 손실 대상 강조 |
| 방어 중·기지 약탈 | 약탈 무리 퇴각 | 결과 처리 완료 | 판매 재개 | 셔터 개방, 손님 복귀, 손실 요약 |

### 6.3 손님 대피와 창구 셔터

1. 약탈 경보가 울리면 새 손님이 줄에 들어오지 않고 모든 창구의 판매를 중단한다.
2. 줄과 창구에 있던 손님은 남쪽 화면 밖으로 대피한다. 줄 순서와 상품 요청은 유지한다.
3. 손님이 계산대 정면에서 모두 빠지면 모든 창구 셔터가 함께 내려온다.
4. 창구 셔터는 목재·금속 덮개로 보이며, 비용·체력·손상·강화 상태가 없다.
5. 셔터는 계산대 정면의 손님 접근만 막는다. 벽·출입문을 대신하지 않으며, 약탈 무리가 기지 안에
   들어오는 것을 막지 못한다.
6. 약탈 무리가 퇴각하면 셔터가 모두 올라가고 손님이 기존 순서로 복귀한다.

### 6.4 방어 동료와 벽·출입문

- 방어 야영지에 배치된 동료는 경보 뒤 출입문으로 이동해 약탈 무리와 자동으로 싸운다.
- 방어 동료가 모두 쓰러졌거나 치료 중이면 남은 약탈 무리가 벽·출입문을 공격한다.
- 벽·출입문은 하나의 방어 시설이며, 하나의 체력·손상 상태를 가진다.
- 벽·출입문이 파괴되면 약탈 무리가 기지 안쪽으로 들어온다. 창구 셔터가 닫혀 있어도 이 진입은 막지
  못한다.
- 벽·출입문이 파괴되지 않은 채 약탈 무리가 퇴각하면 상품과 계산대·운반 중 코인을 잃지 않는다.
- 방어 종료 뒤 벽 손상은 남는다. 수리 비용과 수리 비콘 흐름은
  [`progression-balance.md`](progression-balance.md#45-약탈과-치료)와
  [`base-automation.md`](base-automation.md#5-비콘-건설강화수리-흐름)를 따른다.

### 6.5 약탈 손실

- 손실은 판매대 상품과 메인 기지에 도착하지 않은 코인에만 적용한다.
- 메인 기지에 입고된 돌·나무·코인·뼈와 획득 즉시 보관된 소울은 잃지 않는다.
- 벽·출입문이 파괴된 약탈에서 상품과 코인은 각각 출시 손실률을 적용하고, 개수는 버림해 계산한다.
  1개 이상 보유한 대상의 손실 결과가 0개가 되지 않도록 최소 1개를 잃는다.
- 약탈 대상이 없으면 손실은 0이고, 벽 손상과 방어 동료 부상만 결과로 남을 수 있다.
- 손실률·약탈 무리 규모·벽 최대 체력의 수치 원본은
  [`progression-balance.md`](progression-balance.md#45-약탈과-치료)를 따른다.

## 7. 온라인 직접 방어와 자동 방어

### 7.1 직접 방어

- 약탈 경보가 발생한 순간 플레이어가 동굴 기지에 있으면 직접 방어 모드로 잠근다.
- 직접 방어 모드에서는 플레이어가 이동해 방어 동료와 함께 자동 공격·방어 상황을 확인한다.
- 약탈이 끝나면 약탈 무리 생물을 공식 이름순으로 정렬한 결과 목록을 표시한다.
- 결과 목록 각 행은 생물 이름, 초상화, 영입 가능 여부, `영입`, `재화` 선택을 보여 준다.
- 영입과 재화의 등급별 확률·보상은 탐험에서 쓰러뜨린 생물과 같은 수치 원본을 사용한다.
- 두 수용량 중 하나라도 부족하면 해당 생물의 `영입`을 비활성화하고 부족한 수용량을 표시한다.
- `전부 영입`은 선택하지 않은 모든 생물이 영입 가능하고 두 수용량이 모두 충분할 때만 활성화한다.
- `전부 재화`는 선택하지 않은 모든 생물을 한 번에 재화 결과로 처리한다.
- 플레이어가 방어 중 다른 지역으로 이동하면 방어 동료와 약탈은 계속되고, 결과 목록은 방어 종료 후
  기지에 돌아왔을 때 표시한다. 이동 때문에 영입 가능한 결과를 자동 재화로 바꾸지 않는다.

### 7.2 자동 방어

- 약탈 경보 순간 플레이어가 숲 또는 다른 지역에 있으면 자동 방어 모드로 처리한다.
- 자동 방어는 결과 선택 화면을 만들지 않는다. 약탈 무리 생물은 영입할 수 없다.
- 자동 방어 결과에서 뼈와 등급별 소울은 등짐을 거치지 않고 안전 자원으로 보관한다.
- 자동 방어가 성공하면 상품·코인을 잃지 않고, 방어 동료가 쓰러졌다면 부상 상태로 치료 대기열에
  들어간다.
- 자동 방어가 실패하면 상품·코인 손실, 벽 손상, 부상 결과를 적용한 뒤 치료·판매 재개 순서로 넘어간다.
- 결과 요약은 `방어 성공 여부 → 잃은 상품·코인 → 벽 손상 → 부상·치료 → 안전하게 얻은 뼈·소울`
  순서로 표시한다.

## 8. 부상·치료·복귀

### 8.1 온라인 방어

- 플레이어가 접속해 있는 온라인 방어에서 방어 동료 체력이 0이 되면 치료소의 존재를 확인한다.
- 치료소가 완성되어 있으면 동료는 부상 상태로 치료 대기열에 들어가며 영구 이탈하지 않는다.
- 치료소가 없으면 온라인 방어에서 쓰러진 동료는 영구 이탈한다.
- 부상 동료는 다음 약탈에 출동하지 않고 기지 수용량은 계속 사용한다.
- 치료 비용을 충족하면 대기열 앞 동료부터 치료를 시작한다. 치료 중인 동료가 끝나면 다음 동료가
  자동 시작한다.
- 치료 시간·비용과 동시 치료 수의 출시 기본값은
  [`progression-balance.md`](progression-balance.md#45-약탈과-치료)의 수치를 따른다.

### 8.2 오프라인 방어

- 오프라인 방어에서 쓰러진 방어 동료는 치료소가 없어도 영구 이탈하지 않는다.
- 부상 동료는 인원 제한 없는 치료 대기열에 들어간다. 치료소가 없으면 대기만 하고, 치료소를 완성한
  뒤 치료를 시작한다.
- 치료소가 있으면 오프라인의 적용 시간 동안 온라인과 같은 치료 시간이 흐른다.
- 치료를 마친 동료는 후속 약탈의 방어 야영지로 자동 복귀한다.
- 오프라인 결과 화면에는 치료 완료·치료 중·비용 부족을 각각 구분한다.

## 9. 유지·초기화와 취소

- 해금된 계산대·방어 야영지·벽·출입문·치료소, 시설 강화, 안전 자원과 보유 동료는 세션 종료 뒤
  유지된다.
- 판매대 재고, 계산대 코인, 코인 운반, 약탈 경보·대피·셔터, 벽 손상과 치료 대기열은 운영 상태로
  남고 오프라인 진행의 같은 규칙을 적용한다.
- 손님이 최대 대기 시간으로 떠나면 재고와 코인을 바꾸지 않는다.
- 판매대·계산대에서 플레이어가 뒤로 가거나 이동해도 이미 완료된 판매는 취소되지 않는다. 아직 상품을
  소비하지 않은 창구 손님은 기존 요청을 유지하고, 약탈 경보가 발생하면 대피한다.
- 직접 방어 결과 목록을 닫아도 선택하지 않은 생물 결과는 남아 있다. 결과 목록을 다시 열어 선택할
  수 있으며, `전부 재화`를 선택하기 전까지 영입 기회를 자동 소비하지 않는다.
- 새 게임에서는 방어 시설과 치료소의 해금이 사라지고, 약탈 보상·부상·벽 손상도 초기화된다.

| 상품 품절 | 손님의 요청 말풍선 유지·대기 시간 | 요청 상품 생산 또는 대기 |

| 코인 미입고 | 계산대·운반 중 코인 수량 | 플레이어 또는 전용 일꾼 운반 |

| 직접 방어 결과 | 생물별 영입 가능·재화 선택·수용량 | 개별 선택 또는 일괄 선택 |

### 10.2 시각 방향

- 손님은 대기 줄에서 움직이는 실루엣과 상품 요청 말풍선으로 읽히게 한다. 말풍선은 상품 아이콘과
  요청 상태를 함께 사용해 색을 보지 못해도 구분한다.
- 판매대 재고는 상품의 작은 더미와 수량 표시로, 계산대 코인은 반짝이는 코인 묶음과 수량 표시로
  구분한다. 메인 기지 안전 코인 더미와 계산대 코인의 위치를 섞지 않는다.
- 약탈 경보는 화면 가장자리의 붉은색 계열 경고와 흔들리는 기지 표식, 사운드로 알리되, 세로 화면의
  주요 이동 영역을 가리지 않는다.
- 창구 셔터는 모든 창구에서 같은 순간에 내려가 판매 정지와 방어 준비를 보여 준다.
- 벽·출입문은 균열과 낮아지는 체력 표시로 손상을 보여 주고, 셔터에는 체력바를 표시하지 않는다.
- 부상 동료는 방어 야영지에서 치료소 방향의 아이콘과 부상 표식을 보여 준다.

### 10.3 사운드

- 상품 요청 말풍선이 생길 때 짧은 종소리, 상품 품절 대기는 부드러운 반복음, 판매 완료는 밝은 코인
  소리를 사용한다.
- 약탈 경보는 낮은 북소리와 짧은 경고음을 함께 사용하고, 손님 대피가 끝나 셔터가 내려갈 때 금속·목재
  덮개 소리를 낸다.
- 방어 성공은 상승하는 짧은 화음, 벽 파괴는 낮은 충격음, 상품·코인 손실은 짧은 하강음으로 구분한다.
- 치료 시작은 낮은 안정음, 치료 완료는 밝은 회복음으로 표시한다.

## 11. 상황별 확인 기준

| 확인 상황 | 기대 결과 |
| --- | --- |
| 판매대에 돌 상품 1개 도착 | 남쪽 대기 구역에 손님이 들어오고 상품 요청 말풍선에 같은 상품 아이콘이 표시된다 |
| 요청 상품이 품절 | 해당 손님은 요청을 바꾸지 않고 말풍선을 유지하며 재입고를 기다린다 |
| 여러 창구가 비어 있음 | 한 줄의 선두 손님부터 각 창구에 한 명씩 배정된다 |
| 상품 판매 완료 | 재고 1개가 줄고 계산대 코인이 늘며 손님 말풍선이 사라진다 |
| 계산대 1단계 | 플레이어가 코인을 들고 메인 기지까지 실제 운반할 수 있다 |
| 계산대 첫 강화 완료 | 전용 일꾼 자리 1개가 나타나고, 배치한 일꾼이 코인을 실제 운반한다 |
| 전용 일꾼을 다른 역할로 변경 | 진행 중 코인을 메인 기지에 내려놓은 뒤 코인 운반이 플레이어 방식으로 돌아간다 |
| 첫 판매 직후 | 벽·출입문과 방어 야영지 건설 비콘이 보이고 두 시설 완성 전에는 약탈이 발생하지 않는다 |
| 약탈 경보 발생 | 새 손님과 판매가 멈추고 모든 손님이 순서를 유지한 채 대피한다 |
| 손님 대피 완료 | 모든 계산 창구의 창구 셔터가 동시에 닫힌다 |
| 셔터 폐쇄 중 | 공방 생산과 기지 내부 물류는 계속되고 판매만 멈춘다 |
| 방어 성공 | 상품·코인 손실 없이 셔터가 열리고 손님이 기존 순서로 돌아온다 |
| 벽·출입문 파괴 | 셔터와 관계없이 약탈 무리가 기지 안으로 들어오며 상품·미입고 코인 손실을 처리한다 |
| 직접 방어 완료 | 공식 이름순 생물 결과 목록과 영입·재화 선택을 표시한다 |
| 다른 지역에서 자동 방어 | 결과 선택 없이 뼈·소울을 안전 보관하고 영입 선택은 만들지 않는다 |
| 온라인 치료소 없음 | 쓰러진 방어 동료가 영구 이탈한다 |
| 오프라인 치료소 없음 | 부상 동료가 대기열에서 유지되고 치료소 완성 뒤 치료를 시작한다 |
| 치료 완료 | 동료가 방어 야영지로 자동 복귀해 다음 약탈에 참여한다 |

## 12. 검증 필요와 완료 조건

- 상품 요청 말풍선, 대기 줄, 계산 창구, 코인 운반과 약탈 경고가 세로 화면에서 동시에 읽히는지 확인한다.
- 손님 대피 중 현재 요청과 줄 순서가 유지되는지, 복귀 후 남은 대기 시간이 불공정하게 줄지 않는지
  확인한다.
- 첫 판매 뒤 방어 시설을 짓는 비용과 약탈 손실이 반복 판매를 멈추게 하지 않는지 확인한다.
- 직접 방어 결과 목록에서 수용량 부족, 개별 선택, `전부 영입`, `전부 재화`가 혼동되지 않는지 확인한다.
- 벽·출입문과 창구 셔터가 서로 다른 방어 역할로 보이고, 셔터에 체력·수리 비용이 잘못 표시되지 않는지
  확인한다.
- 오프라인 약탈 뒤 안전 코인·미입고 코인·판매대 상품·부상 동료의 결과 요약이 서로 어긋나지 않는지
  확인한다.
