# 온보딩·HUD·접근성 기획서

> 문서 상태: 검토 중
>
> 담당 범위: 시작부터 첫 영입·첫 판매·첫 방어까지의 온보딩, 전체 HUD, 시설 상태와 부족 피드백,
> 세로 화면 접근성, 기지·자동화·환경의 시각·연출·사운드 방향
>
> 규칙 원본: 이 문서는 첫 사용자 경험과 공통 정보 표현의 단일 원본이다.
>
> 상위 규칙: [`core-gameplay.md`](core-gameplay.md)의 조작·코어 순환·UI 확정 규칙을 따른다.
>
> 세부 원본: 기지·물류는 [`base-automation.md`](base-automation.md), 판매·방어는
> [`sales-defense.md`](sales-defense.md), 반복 수치는 [`progression-balance.md`](progression-balance.md)를 따른다.

## 1. 목적과 범위

### 1.1 플레이어 가치

처음 접속한 플레이어가 상하좌우 이동만으로 자동 공격·채집을 이해하고, 동굴에서 생물을 영입해
일꾼으로 배치한 뒤, 상품 판매와 기지 방어가 하나의 순환이라는 사실을 짧은 흐름 안에 알게 한다.
화면은 플레이어가 지금 해야 할 일, 부족한 것, 위험한 것과 이미 안전해진 것을 한눈에 구분하게 한다.

### 1.2 포함 범위

- 시작 상태와 첫 이동·채집·생물 대응·영입 안내
- 첫 동료를 일꾼으로 바꾸고 채석장·공방·판매대·계산대까지 연결하는 흐름
- 첫 판매 뒤 벽·출입문과 방어 야영지를 건설하고 첫 약탈 경보·방어를 이해하는 흐름
- 항상 보이는 HUD, 상황별 시설 패널, 자원 부족·수용량·대기·손실 피드백
- 2D 아이소메트릭 세로 화면의 터치 접근성, 읽기 순서, 시각·청각 대체 피드백
- 기지 단계 변화, 실제 물류, 손님·셔터·방어·치료의 공통 시각·연출·사운드 원칙
- 오프라인 복귀 요약과 다음 행동 안내

### 1.3 제외 범위

- 화면의 픽셀 좌표, 코드·데이터 구조, 저장 구조와 분석 이벤트
- 최종 색상 팔레트, 생물·건축물의 개별 이름·외형
- 공방 생산·파견·판매·약탈의 판정 규칙과 수치는 각 원본 문서를 참조한다.
- 별도 목표 목록, 계정 성장, 유료·광고 유도는 출시 범위에 넣지 않는다.

## 2. 상태와 학습 순서

### 2.1 결정 상태

- **확정**: 모바일 웹, 2D 아이소메트릭 세로 화면, 상하좌우 이동 중심 조작, 거리 조건 자동 행동,
  메인 기지에서의 코어 순환이다.
- **가정**: 설명을 한 번에 길게 보여 주지 않고 행동 직전의 짧은 안내와 시설별 반복 힌트로 학습시킨다.
- **검증 필요**: 플레이어가 텍스트 도움 없이 첫 상품 판매와 첫 약탈 경보의 원인을 이해하는지 확인한다.
- **미정 없음**: 출시 온보딩과 HUD에는 각 단계의 목표·조건·실패 처리·다음 행동이 있다.

### 2.2 학습 원칙

1. 화면에 한 번에 새로운 규칙 하나만 강조한다.
2. 설명 뒤에 즉시 같은 행동을 수행하게 하고, 완료 결과를 기지의 변화로 보여 준다.
3. 자동 행동은 대신 수행하지 않고, 대상 접근·범위·우선순위와 결과를 표시한다.
4. 실패해도 안전 자원·영구 진행·다음 행동을 분명히 보여 준다.
5. 이미 배운 규칙은 작은 아이콘과 상태 문구로 다시 확인할 수 있게 한다.

## 3. 시작부터 첫 영입까지

### 3.1 시작 상태

- 플레이어는 모닥불 1단계의 메인 기지 입고 범위 안에서 시작한다.
- 화면에는 이동 안내, 플레이어 체력, 등짐, 안전 자원과 고정 포탈이 보인다.
- 공방·판매대·계산대는 잠금 없이 보이지만, 공방에는 돌 상품 생산만, 계산대에는 계산 창구 하나만
  현재 이용 가능하다고 표시한다.
- 방어 야영지·벽·출입문·치료소는 아직 노출하지 않는다. 첫 판매 뒤 방어 시설 건설 비콘이 나타난다.

### 3.2 첫 이동·채집

1. 첫 안내는 `상하좌우로 이동해 보세요`로 표시한다.
2. 플레이어가 동굴의 돌 가까이 가면 자원 채집 범위와 채집 중 표시를 보여 준다.
3. 등짐에 돌이 쌓이면 등짐 아이콘의 현재량/한도를 강조한다.
4. 메인 기지 쪽으로 돌아오면 입고 범위를 윤곽으로 표시하고, 접근 시 돌 더미가 늘어나는 연출을 한다.
5. 포탈에 접근하면 숲 이동이 가능한 점을 알려 주지만, 첫 영입 전에는 이동을 강제하지 않는다.

등짐이 가득 차면 `등짐이 가득 찼습니다. 자원 채집은 멈추지만 이동과 생물 대응은 계속됩니다.`를 표시한다.
채집만 멈추고 이미 가진 자원·이동·생물 대응은 계속된다는 core 규칙을 같은 문구로 반복한다.

### 3.3 첫 생물 대응과 영입

1. 중립 생물의 공격 범위에 접근하면 대상 표시와 자동 공격 아이콘을 보여 준다.
2. 적대 생물이 함께 범위에 들어오면 적대 생물 우선순위가 적용된다는 경고를 표시한다.
3. 생물이 쓰러지면 생물 아래에 `영입`과 `재화` 선택, 각 선택의 짧은 결과를 표시한다.
4. 영입 선택에는 동행 수용량·기지 수용량을 각각 현재량/한도로 보여 준다.
5. 영입 선택 시 생물이 동료가 되고, 역할 선택 패널에서 탐험 동료·일꾼·방어 동료의 차이를 보여 준다.
6. 첫 영입 동료는 일꾼으로 바꾸는 안내를 바로 보여 주고, `역할 변경`에는 비용이 없음을 표시한다.

첫 영입 전 영입 선택이 두 번 연속 실패하면 다음에 만나는 동굴 일반 생물에서 첫 영입 선택을 보장하는
온보딩 보정을 사용한다. 이 보정은 첫 영입이 끝나면 사라지고, 이후 확률은
[`progression-balance.md`](progression-balance.md#41-플레이어-현장-채집과-생물-결과)의 기본값을 사용한다.
보정을 사용했는지는 화면에 확률 숫자로 노출하지 않고 `이번에는 영입 기회가 열렸습니다`로만 알린다.

## 4. 첫 일꾼부터 첫 판매까지

### 4.1 역할 변경과 채석장

1. 영입 직후 역할 패널을 열고 `일꾼`을 가장 먼저 보여 준다.
2. `일꾼` 설명은 `기지의 자원·상품·코인을 실제로 옮기는 동료`로 쓴다.
3. 역할을 일꾼으로 바꾸면 채석장 파견을 강조하고, 빈 파견 자리와 `배치` 행동을 표시한다.
4. 일꾼이 채석장에서 돌을 싣고 메인 기지로 걷는 모습을 카메라 추적 또는 경로 강조로 보여 준다.
5. 메인 기지 입고 순간 돌 안전 자원과 돌 더미가 함께 늘어나는 것을 표시한다.

공식 용어 설명은 [`terminology.md`](terminology.md)의 `일꾼`, `채석장`, `파견`, `물류` 정의를 따른다.
운반은 화면에서 사라졌다가 수량만 늘어나는 방식으로 표현하지 않는다.

### 4.2 첫 공방 생산

1. 돌이 메인 기지에 도착하면 공방 위에 `돌 상품` 아이콘과 필요한 돌을 표시한다.
2. 일꾼이 재료를 공방으로 옮긴 뒤 생산 시간이 시작되는 모습을 보여 준다.
3. 생산 중에는 상품 아이콘·남은 시간·다음 목적지를 표시한다.
4. 완성 상품이 판매대에 도착하면 판매대 재고가 늘고 남쪽 대기 구역에 손님이 들어온다.
5. 손님 머리 위의 상품 요청 말풍선을 눌러도 판매 규칙이 바뀌지 않으며, 말풍선이 상품을 알려 주는
   표시라는 점을 짧게 안내한다.

생산 재료·시간·판매가는 [`progression-balance.md`](progression-balance.md#43-공방과-판매)를 참조한다.
공방 생산 중 재료가 부족해지는 경우는 이미 시작한 생산을 취소하지 않고, 다음 생산이 멈추며 부족 수량을
표시한다.

### 4.3 첫 판매와 방어 공개

1. 줄 선두 손님이 빈 계산 창구로 이동한다.
2. 상품 1개가 소비되고 계산대 코인이 생기는 순간 `판매 완료`와 코인 운반 안내를 표시한다.
3. 시작 계산대에서는 플레이어가 코인을 들어 메인 기지까지 운반한다.
4. 첫 판매 완료 뒤 화면을 잠깐 멈추고 계산대 양옆의 벽·출입문·방어 야영지 건설 비콘을 공개한다.
5. `상품을 지키려면 두 방어 시설을 모두 완성하세요`라는 다음 목표를 표시한다.

첫 판매 완료는 별도 단계나 목표가 아니라 코어 순환의 결과다. 판매대·계산대 규칙은
[`sales-defense.md`](sales-defense.md#3-판매대와-손님)를 참조한다.

## 5. 첫 방어까지

### 5.1 방어 시설 건설

1. 벽·출입문과 방어 야영지 비콘을 각각 선택할 수 있게 한다.
2. 각 비콘에 현재 안전 자원/필요 비용과 시설이 하는 일을 표시한다.
3. 한 시설을 완성하면 다른 시설을 다음 목표로 강조하고, 한쪽만 완성된 동안 약탈이 시작되지 않음을
   표시한다.
4. 두 시설이 모두 완성되면 `약탈 경보를 받을 준비가 되었습니다`를 표시한다.

비콘의 투입·중도 이탈·반환은 [`base-automation.md`](base-automation.md#5-비콘-건설강화수리-흐름),
비용은 [`progression-balance.md`](progression-balance.md#52-시설-건설과-강화-비용)를 참조한다.

### 5.2 첫 약탈 경보와 방어

- 첫 방어 시설 완성 뒤 안전하지 않은 상품·코인 가치가 조건에 도달하면 약탈 경보 설명을 표시한다.
- 첫 경보에서는 화면 상단에 `손님 대피 → 창구 셔터 폐쇄 → 방어 → 손님 복귀` 순서를 짧은 아이콘으로
  보여 준다.
- 손님이 대피하고 창구 셔터가 모두 닫히는 순간, 셔터는 벽·출입문이 아니라 판매 정지 표시임을 안내한다.
- 플레이어가 기지에 있으면 방어 동료의 이동과 벽·출입문 체력을 함께 보여 준다.
- 플레이어가 다른 지역에 있으면 접속 뒤 결과 요약으로 자동 방어가 처리됐음을 보여 준다.
- 방어가 끝나면 성공·벽 손상·상품·코인 손실·부상·치료를 각각 분리해 보여 준다.

첫 약탈 경보의 온보딩 보정은 두 방어 시설 완성 후 조건에 도달한 첫 확인 시점의 약탈 발생을 보장한다.
이후 약탈은 [`progression-balance.md`](progression-balance.md#45-약탈과-치료)의 기본 확률을 사용한다.
보정은 첫 방어를 이해시키기 위한 일회성 경험이며, 보상·손실 규칙을 바꾸지 않는다.

## 6. 전체 HUD와 시설 상태

### 6.1 항상 보이는 정보

세로 화면의 어느 지역에서도 다음 정보를 한 번에 확인할 수 있게 한다.

| 정보 | 표시 내용 | 상태 변화 |
| --- | --- | --- |
| 플레이어 체력 | 현재 체력/최대 체력, 위험 표시 | 체력 30% 이하에서 큰 경고, 0이면 코어 패배 흐름 |
| 등짐 | 돌·나무·뼈 현재량/운반 한도 | 가득 참, 입고, 패배 시 각각 다른 아이콘 |
| 안전 자원 | 돌·나무·코인·뼈·소울 현재량 | 재화별 아이콘·수량, 소울은 별도 빛 표시 |
| 동료 수용량 | 동행 현재량/한도, 기지 현재량/한도 | 영입 가능·부족·최대 상태를 분리 |
| 현재 목표 | 가장 가까운 행동 1개 | 이동, 입고, 영입, 배치, 생산, 방어 중 하나 |
| 기지 위험 | 약탈 경보, 벽 체력, 부상 동료 수 | 평상시 숨김, 경보·손상·부상 때 우선 노출 |
| 오프라인 결과 | 새 결과가 있음을 알리는 표시 | 접속 직후 요약 진입 |

- 등짐과 안전 자원을 같은 숫자나 같은 색으로 합치지 않는다.
- 소울은 즉시 안전해도 수용량 확장에 쓰이는 희귀 재화임을 별도 아이콘으로 표시한다.
- 체력·경보·벽 손상은 색만으로 전달하지 않고 아이콘·문구·움직임을 함께 사용한다.

### 6.2 시설 상태 표현

| 상태 | 표시 문구 예시 | 플레이어가 할 수 있는 일 |
| --- | --- | --- |
| 잠김 | `메인 기지 4단계에서 공개` | 조건 확인 |
| 공개·미건설 | `코인 60개 필요` | 비콘으로 이동해 건설 |
| 사용 가능 | `공방 생산 준비` | 재료 또는 일꾼 배치 |
| 생산·운반 중 | `돌 상품 · 12초 남음` | 진행·목적지 확인 |
| 재료 부족 | `돌 2개 부족` | 채집·채석장 파견 |
| 재고 대기 | `판매대에 상품 0개` | 공방 생산 확인 |
| 자리 부족 | `채석장 파견 자리 없음` | 메인 기지 성장·기존 역할 변경 |
| 강화 잠김 | `메인 기지 6단계 필요` | 기지 성장 |
| 손상 | `벽 내구도 40/100 · 수리 필요` | 수리 비콘 이동 |
| 부상·치료 | `치료 대기 2명 · 코인 5개 부족` | 치료 비용 확보 |
| 약탈 경보 | `손님 대피 중 · 창구 셔터 닫힘` | 방어·결과 확인 |
| 완료 | `건설 완료 · 다음 단계는 재진입` | 비콘에서 나갔다 재진입 |

문구의 숫자 단위는 [`progression-balance.md`](progression-balance.md)의 단위를 따른다. 부족 문구는
항상 부족 항목과 남은 수량을 함께 말하며, `할 수 없습니다`만 단독으로 쓰지 않는다.

### 6.3 상황별 패널

- 시설을 눌렀을 때 화면 중앙을 막는 큰 창 대신, 시설 가까이에 현재 상태·다음 행동·비용을 보여 주는
  짧은 패널을 연다.
- 비용·확률·시간은 선택 전에 보여 주고, 실행 불가 상태에서는 선택을 비활성화하되 부족 이유를 유지한다.
- 패널을 닫거나 뒤로 가도 이미 완료된 생산·판매·운반·건설은 취소하지 않는다.
- 뒤로 가기 후에도 `현재 목표`와 해당 시설의 상태 아이콘을 유지해 다음 행동을 찾게 한다.

## 7. 오프라인 복귀 요약

### 7.1 표시 순서

오프라인 진행은 마지막 접속 이후 최대 24시간만 적용한다. 복귀 화면은 다음 순서로 보여 준다.

1. 적용 시간과 오프라인 진행이 상한에 걸렸는지
2. 메인 기지에 안전하게 도착한 돌·나무·코인·뼈·소울
3. 생산 완료 상품과 판매된 상품·생성된 코인
4. 약탈 경보와 방어 성공·실패, 잃은 상품·코인
5. 부상·치료 완료·치료 중·비용 부족
6. 현재 파견·생산·운반 중인 흐름
7. 다음으로 추천하는 한 가지 행동

### 7.2 복귀 예외

- 오프라인 현장 탐험·자동 공격·현장 채집은 결과에 포함하지 않는다.
- 오프라인 약탈의 생물은 영입할 수 없고, 뼈·소울만 안전 자원으로 요약한다.
- 메인 기지 도착 전 코인과 판매대 상품만 약탈 손실 대상으로 표시한다.
- 손실이 없으면 `지켜 냈습니다`를, 손실이 있으면 상품·코인의 손실 수량과 다음 방어 행동을 함께
  표시한다.
- 24시간을 초과한 경우 초과분을 보상이나 손실로 만들지 않고 `최대 24시간까지 적용`을 표시한다.
- 결과 요약을 닫아도 적용된 진행과 안전 자원은 유지하며, 진행 중인 파견·생산·치료 아이콘은 HUD에
  남긴다.

## 8. 세로 화면과 접근성

### 8.1 입력

- 기본 조작은 화면 한쪽의 네 방향 이동 영역이며, 상하좌우를 동시에 누르면 마지막으로 인식한 한 방향만
  유지한다.
- 이동 영역과 주요 선택의 터치 대상은 최소 44 CSS 픽셀로 제공한다. 선택 사이에는 오입력을 줄일
  여백을 둔다.
- 자동 공격·자원 채집·비콘 투입은 거리 조건을 만족하면 시작되므로 작은 선택을 정확히 누르지 않아도 된다.
- 플레이어가 손님·시설·자원을 누르면 이동 명령으로 오해하지 않도록 선택 강조와 현재 목표를 분리한다.

### 8.2 읽기와 시야

- 아이소메트릭 사선 때문에 플레이어·대상·일꾼·손님이 겹칠 때는 대상 외곽선과 목적지 표식을 우선한다.
- 화면 아래쪽 대기 줄과 위쪽 HUD가 서로 가리지 않게 하며, 약탈 경보는 전투 대상을 가리지 않는 가장자리
  영역에 표시한다.
- 자원·상품·소울·경보는 색, 모양, 아이콘, 문구 중 최소 두 가지 표현을 함께 사용한다.
- 말풍선과 체력·진행 표시는 배경 안개와 겹쳐도 읽히도록 불투명한 외곽선과 충분한 대비를 사용한다.
- 확대했을 때도 핵심 HUD와 현재 목표가 화면 밖으로 밀려나지 않게 하고, 작은 화면에서는 세부 목록을
  세로 스크롤로 제공한다.

### 8.3 동작·소리 대체

- 기지 확장 카메라 이동, 셔터 하강, 손님 대피와 약탈 경보는 짧은 애니메이션·문구·아이콘으로 동시에
  전달한다.
- 사운드를 끈 플레이어도 경보·판매 완료·비콘 완료·치료 완료를 진동 또는 시각 변화로 확인할 수 있게
  한다.
- 빠른 카메라 이동·화면 흔들림·발광 섬광은 줄이기 옵션을 제공하고, 끄면 위치 변화와 상태 아이콘은
  유지한다.
- 자동 이동과 실제 운반의 차이는 발자국·운반 아이콘·목적지 선으로 보여 주어 소리를 사용할 수 없을
  때도 알 수 있게 한다.

## 9. 기지·환경 시각 방향

- `신비로운 자연 판타지` 분위기 안에서 발광 식물, 소울의 빛, 부드러운 안개, 돌·나무·천·금속의 자연
  소재를 사용한다.
- 모닥불·텐트 단계는 야외 자원 더미와 가까운 작업 동선으로 읽히고, 돌 거점 이후는 열린 단면 창고와
  정리된 물류 흐름으로 읽힌다.
- 큰 단계 변화는 모닥불 → 텐트 → 돌 거점 → 돌·나무 거점 → 판타지 완성 거점의 재질 변화를 따른다.
  정확한 색상·생물·건축물 외형은 별도 시각 기획에서 승인한다.
- 시각 효과는 실제 판정과 혼동되지 않게 한다. 예를 들어 자원 더미 크기는 보유량 구간을 보여 주지만,
  실제 안전 자원 수량을 대신하지 않는다.
- 기지에서의 실제 운반은 자원 더미, 일꾼의 손, 목적지, 입고 반짝임의 네 단계로 보인다.

## 10. 공통 사운드 방향

| 피드백 | 소리 의미 | 소리 없이 보이는 대체 표현 |
| --- | --- | --- |
| 자동 공격 시작 | 대상 대응 시작 | 대상 외곽선·공격 아이콘 |
| 자원 채집 시작 | 자원 수집 시작 | 자원 반짝임·채집 진행 |
| 등짐 가득 | 채집만 중단 | 등짐 테두리·`채집 중단` |
| 메인 기지 입고 | 위험한 자원이 안전해짐 | 더미 증가·안전 자원 숫자 상승 |
| 상품 완성·판매 | 수입 순환 진행 | 상품 이동·코인 생성 |
| 비콘 완료 | 건설·강화·수리 완료 | 비콘 빛·완료 문구 |
| 약탈 경보 | 판매 중단·방어 시작 | 화면 가장자리 경고·손님 대피·셔터 |
| 방어 실패 | 손실·벽 손상 가능 | 손실 수량·벽 균열·부상 아이콘 |
| 치료 완료 | 방어 동료 복귀 | 동료가 야영지로 이동 |

사운드 방향은 특정 상용 게임의 효과음이나 화풍을 모방하지 않는다. 자연 소재와 발광 판타지의 분위기를
사용하되, 상태 전달이 장식보다 우선한다.

## 11. 유지·초기화와 실패 처리

- 온보딩 완료 표시는 플레이어 진행으로 유지하며, 이미 설명한 단계의 강제 안내를 반복하지 않는다.
- 도움말 아이콘을 누르면 이동·자동 행동·등짐·영입·일꾼·판매·방어 설명을 다시 볼 수 있다.
- 플레이어가 첫 영입 전에 패배하면 등짐만 잃고 메인 기지·다음 목표·안전 자원은 유지한다.
- 첫 판매 전에 재료가 부족하면 현장 채집·채석장 파견·일꾼 배치 중 가장 가까운 해결 행동을 강조한다.
- 첫 방어에서 벽이 파괴되면 손실 수량, 수리 비콘, 치료소·방어 동료 상태를 보여 주고 재시작을 요구하지
  않는다.
- 온보딩 설명 중 앱을 닫아도 이미 완료된 영입·판매·시설 공개는 유지되며, 다시 접속하면 마지막으로
  완료한 단계의 다음 목표를 표시한다.
- 새 게임에서는 온보딩 안내와 기지 진행을 처음부터 시작한다. 기존 진행을 선택적으로 재분배하는
  기능은 출시 범위에 넣지 않는다.

| 확인 상황 | 기대 결과 |

| 메인 기지 입고 | 입고 범위 표시와 자원 더미·안전 자원 수량이 함께 갱신된다 |

| 첫 약탈 경보 | 손님 대피, 셔터 폐쇄, 방어, 손님 복귀 순서를 아이콘과 문구로 보여 준다 |
| 방어 실패 | 상품·코인 손실, 벽 손상, 부상과 다음 행동을 각각 표시하고 재시작시키지 않는다 |
| 다른 지역에서 오프라인 복귀 | 적용 시간 24시간 상한, 안전 자원, 생산·판매·약탈·치료 결과를 순서대로 요약한다 |
| 작은 세로 화면 | HUD와 현재 목표가 고정되고 세부 목록은 스크롤되며, 겹친 대상은 외곽선으로 선택된다 |
| 소리와 동작을 끔 | 경보·완료·손실·치료를 문구·아이콘·진동 또는 시각 변화로 확인할 수 있다 |

## 13. 검증 필요와 완료 조건

- 첫 영입까지 새로 배우는 개념이 이동·자동 행동·영입·역할 중 한 번에 하나씩 제시되는지 확인한다.
- 첫 영입 후 첫 상품 판매까지 플레이어가 `일꾼 → 채석장 → 공방 → 판매대 → 계산대`의 관계를
  도움말 없이 설명할 수 있는지 확인한다.
- 첫 약탈 경보에서 셔터를 벽으로 오해하지 않고, 상품·코인이 안전 자원으로 바뀌는 시점을 구분하는지
  확인한다.
- 44 CSS 픽셀 터치 대상과 세로 스크롤 목록이 한 손 조작에서 오입력·가림을 줄이는지 확인한다.
- 색을 구분하기 어려운 상황에서도 아이콘·모양·문구만으로 등짐 가득, 재료 부족, 경보, 부상과 완료를
  구분하는지 확인한다.
- 오프라인 결과가 숫자만 나열하지 않고 손실·부상·다음 행동을 보여 주는지 확인한다.
