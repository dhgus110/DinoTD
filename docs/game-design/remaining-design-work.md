# Dino TD 남은 기획 작업과 병렬 세션 인계

> 문서 상태: 확정
>
> 목적: 통합 수정 이후 남은 기획 작업의 순서, 병렬 세션 담당 범위와 병합 조건을 관리한다.
>
> 제품 범위 원본: `jurassic-tower-defense-gdd.md`
>
> 공식 용어 원본: `terminology.md`

## 1. 현재 기준 상태

- 제품 범위는 봄·여름·겨울 3개 월드, 총 30개 스테이지다.
- 통합 수정 기준 커밋은 `53f3ed6`이다.
- 봄 월드 후속 브랜치는 `design/spring-vertical-slice`다.
- 여름 월드 후속 브랜치는 `design/summer-world`다.
- 두 브랜치는 같은 기준 커밋에서 시작한다.
- 제품 범위 밖의 계절 월드는 제작·검토·확장 대상에 포함하지 않는다.

## 2. 병렬 작업 시작 조건

1. 통합 담당자가 `main`과 두 작업 브랜치를 원격 저장소에 푸시한다.
2. 각 세션은 서로 다른 Git 작업 폴더에서 담당 브랜치를 체크아웃한다. 같은 작업 폴더에서 두 브랜치를 동시에 작업하지 않는다.
3. 각 세션은 `.rules/work-start.md`에 따라 전체 Markdown과 현재 변경 상태를 확인한다.
4. 각 세션은 아래 수정 허용 파일 밖의 문서를 직접 변경하지 않는다.
5. 공통 규칙 변경이 필요하면 해당 문서를 수정하지 않고 세션 인계에 문제와 추천안을 기록한다.

## 3. 세션 1: 봄 월드 완성

- 담당 브랜치: `design/spring-vertical-slice`
- 새 원본 문서: `spring-world-production-spec.md`
- 수정 허용 파일: `spring-world-production-spec.md`, 신규·변경 용어가 있을 때의 `terminology.md`
- 규칙 원본: `spring-stage-content.md`, `stage-map-rules.md`, `combat-system-rules.md`,
  `card-draw-rules.md`, `economy-barricade-rules.md`, `tower-upgrade-card-spec.md`,
  `ultimate-card-spec.md`

### 3.1 완료할 작업

- 1-1~1-10의 실제 경로 형태와 출현 지점·개척지 관문·타워 슬롯·방벽 슬롯·나무·채집 건물 배치를 작성한다.
- 각 스테이지의 초기 카메라 위치와 반드시 보여야 하는 영역을 정한다.
- 튜토리얼의 시작 조건, 진행 차단, 완료 조건, 실패·취소와 재안내 흐름을 확정한다.
- 카드·경제·승리·실패 상황에서 플레이어에게 보여줄 문구를 작성한다.
- 봄 월드 제작에 필요한 아트·사운드 목록과 각 항목이 전달할 정보를 작성한다.
- 정상·실패·경계 상황을 확인할 수 있는 상황별 확인 사례를 작성한다.

### 3.2 제외 범위

- 엔진 좌표 형식, 데이터 구조, 내부 식별자와 구현 코드
- 공통 전투·카드·맵·경제 규칙과 기존 수치 변경
- 여름·겨울 월드 콘텐츠
- 저장 구조, 기술 성능 기준과 목표 이용 연령

### 3.3 완료 조건

- 1-1~1-10 모두에 경로·배치·초기 화면·튜토리얼·문구·제작 목록이 빠짐없이 연결돼 있다.
- 기존 원본과 충돌하는 내용이 없다.
- 신규·변경 용어가 있다면 용어집과 `용어 병합 메모`가 작성돼 있다.
- 세션 인계 형식으로 확정·가정·미정·검증 필요와 병합 주의점을 보고한다.

## 4. 세션 2: 여름 월드 콘텐츠

- 담당 브랜치: `design/summer-world`
- 새 원본 문서: `summer-stage-content.md`
- 수정 허용 파일: `summer-stage-content.md`, 신규·변경 용어가 있을 때의 `terminology.md`
- 규칙 원본: `jurassic-tower-defense-gdd.md`, `stage-map-rules.md`, `combat-system-rules.md`,
  `card-draw-rules.md`, `economy-barricade-rules.md`, `tower-upgrade-card-spec.md`,
  `ultimate-card-spec.md`

### 4.1 완료할 작업

- 여름 월드의 플레이 목적과 환경 기믹을 확정한다.
- 여름 월드에 새로 등장할 일반·알파·보스 공룡의 역할과 규칙을 확정한다.
- 2-1 일렉트릭 타워부터 2-10까지의 학습·해금 순서를 정한다.
- 2-1~2-10의 맵 구조, 웨이브별 공룡 구성, 경제 시작값과 예정 일반 카드 선택 횟수를 작성한다.
- 환경 기믹과 공룡 규칙의 정상·실패·경계 상황을 확인할 사례를 작성한다.

### 4.2 제외 범위

- 기존 공통 전투·카드·맵·경제 규칙과 수치 변경
- 엔진 좌표 형식, 데이터 구조, 내부 식별자와 구현 코드
- 봄·겨울 월드 콘텐츠
- 저장 구조, 기술 성능 기준과 목표 이용 연령

### 4.3 완료 조건

- 환경 기믹과 신규 공룡의 목적·진행·제한·종료·실패 규칙이 확정돼 있다.
- 2-1~2-10 모두에 학습·해금, 맵 구조, 웨이브, 경제 시작값과 카드 선택 횟수가 있다.
- 기존 공통 규칙 변경이 필요하면 직접 수정하지 않고 세션 인계에 기록한다.
- 신규·변경 용어가 있다면 용어집과 `용어 병합 메모`가 작성돼 있다.
- 세션 인계 형식으로 확정·가정·미정·검증 필요와 병합 주의점을 보고한다.

## 5. 병합 순서

1. 세션 1과 세션 2가 각각 담당 브랜치에 작업을 커밋하고 작업 폴더를 깨끗하게 만든다.
2. 통합 담당자는 세션 1을 먼저 병합하고 전체 Markdown을 점검한다.
3. 세션 2를 병합하면서 용어집 충돌과 공통 규칙 변경 요청을 확인한다.
4. 규칙 원본 소유권, 동일 수치, 공식 용어, 진행 순서와 직접 충돌을 각각 검사한다.
5. 상대경로, UTF-8, 병합 표시와 `git diff --check`를 확인한다.
6. 실질적인 기획 충돌은 임의로 수정하지 않고 사용자에게 선택지와 영향을 보고한다.

## 6. 병합 이후 남은 작업

### 6.1 겨울 월드 콘텐츠

- 여름 월드 확정 후 3-1~3-10의 환경 기믹, 신규 공룡, 학습·해금, 맵 구조, 웨이브,
  경제 시작값과 예정 일반 카드 선택 횟수를 기획한다.
- 봄·여름에서 확정한 콘텐츠 작성 기준을 먼저 교차검증한 뒤 시작한다.

### 6.2 웨이브 체크포인트의 플레이어 경험

- 체크포인트에서 보존되는 플레이어 상태와 초기화되는 상태를 구분한다.
- 앱 완전 종료, 카드 선택 중 종료와 웨이브 복원 뒤 플레이어가 보게 되는 결과를 확정한다.
- 저장 데이터 구조와 구현 방식은 다루지 않는다.

### 6.3 봄 월드 플레이테스트

- 봄 월드 클라이언트가 준비되면 난이도와 라이프 손실 없는 통과 여유를 확인한다.
- 카드 선택 중단 빈도와 연속 선택 피로도를 확인한다.
- 목재 생산과 타워 이동·일꾼·채집 효율·방벽 사이의 경제 선택을 확인한다.
- 최대 타워 슬롯·나무 수와 48×18타일 맵의 가독성과 오선택을 확인한다.
- 검증 결과가 공통 규칙 변경을 요구하면 사용자 승인 후 원본을 수정한다.

### 6.4 클라이언트 개발 담당

- 기술 스택과 네이티브 래퍼
- 최소 지원 기기·운영체제·화면비
- 목표 성능과 기준 기기
- 비유혈 카툰 처치 표현을 기준으로 한 목표 이용 연령
