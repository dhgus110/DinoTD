# Dino TD 작업 시작 규칙

## 목적

- 모든 작업에서 기존 결정, 공식 용어와 문서 작성 원칙을 빠뜨리지 않는다.
- 두 개 이상의 Codex 세션이 함께 작업할 때 기존 변경을 덮어쓰거나 같은 파일을 동시에 수정하는 충돌을 방지한다.
- 게임의 핵심 규칙과 순수 콘텐츠를 일관된 대화로 확정하고, 구현 세부가 기획 범위에 섞이지 않게 한다.

## 기획 작업 범위

### 기본 포함

- 플레이 결과를 결정하는 시작 조건, 진행 순서, 플레이어 선택, 제한, 우선순위와 종료·실패 조건
- 비용과 보상, 계산식, 밸런스 수치와 플레이어가 확인하는 화면 피드백
- 한 판 종료 후 무엇이 유지되거나 초기화되는지처럼 플레이어 경험에 직접 영향을 주는 규칙
- 선택 실패, 취소와 조건 미충족처럼 플레이어가 정상 플레이에서 겪을 수 있는 예외 상황

### 기본 제외

- 코드 구조와 구현용 논리
- 자료형, 데이터 구조, 데이터 컬럼과 내부 식별자
- 처리 알고리즘
- 저장 형식, 저장 시점, 복원 구조와 데이터 이전 방식
- 데이터 손상, 누락 데이터와 실행 중 오류 처리
- 분석 이벤트, 성과 지표와 기술 성능 기준

기본 제외 항목은 사용자가 별도로 요청하고 범위를 합의한 경우에만 다룬다. 기존 기획 문서에 이미 있는 기본 제외 항목을 이 규칙 변경만으로 삭제하지 않는다.

## 매 작업 시작 전 필수 절차

1. `git rev-parse --show-toplevel`로 현재 Git 작업 폴더의 프로젝트 루트를 확인한다.
2. `git branch --show-current`와 `git status --short`로 현재 세션의 브랜치, 다른 세션이나 사용자가 만든 변경사항을 확인한다.
3. `rg --files --hidden -g '*.md' -g '!.git/**'`로 숨김 폴더를 포함한 프로젝트 루트 아래의 모든 Markdown 파일을 찾는다.
4. 검색된 Markdown 파일을 예외 없이 처음부터 끝까지 모두 읽는다.
5. 긴 문서의 출력이 잘리면 나누어 읽어 마지막 줄까지 확인한다.
6. 읽은 문서에서 현재 작업과 관련된 확정 규칙, 공식 용어, 미정 사항과 검증 필요 사항을 구분한다.
7. 기획 또는 용어 작업이면 `docs/guidelines/DESIGNER_GUIDE.md`의 담당 절차와 품질 기준을 적용한다.
8. 문서 사이에 충돌이 있으면 `AGENTS.md`에 정의된 지침 우선순위를 확인하고, 그래도 해결되지 않으면 임의로 한쪽을 선택하지 말고 충돌 위치와 선택지를 사용자에게 알린다.
9. 다른 세션이 변경 중인 것으로 보이는 파일은 덮어쓰지 않는다. 같은 파일을 수정해야 한다면 먼저 사용자와 작업 소유 범위를 정한다.
10. 작업의 목적, 규칙 원본 문서, 참조 문서, 수정 허용 파일, 담당 세션과 제외 범위를 밝힌다.
11. 위 절차가 끝난 뒤에만 분석, 기획 제안, 파일 작성 또는 구현을 시작한다.

## 읽기 범위

- 루트의 `AGENTS.md`와 그 밖의 모든 Markdown 파일
- `.rules` 안의 모든 Markdown 파일
- `docs` 아래의 기획서, 세부 규칙, 용어집과 작성 지침
- 이후 새로 추가되는 모든 Markdown 파일
- Git에 아직 추가되지 않은 Markdown 파일도 읽기 대상에 포함한다.

## 작업 중 재확인

- 작업 도중 다른 세션의 변경이 감지되면 변경된 Markdown 파일을 다시 읽는다.
- 문서를 수정하기 직전에 해당 문서의 최신 내용과 `git status --short`를 다시 확인한다.
- 새 용어나 규칙을 추가할 때는 `docs/game-design/terminology.md`와 관련 규칙의 단일 원본을 먼저 확인한다.
- 이미 확정된 질문은 새로운 충돌이나 영향이 발견되지 않는 한 다시 묻지 않는다.
- 확정 사항을 다시 논의해야 하면 기존 결정, 새로 발견한 문제와 변경 영향을 먼저 설명한다.
- 현재 브랜치, 담당 세션과 수정 허용 파일이 일치하지 않으면 파일을 수정하지 않는다.

## 전제 질문지 운영

1. 기획 질문 전에 필요한 전체 전제 항목과 결정 순서를 정한다.
2. 질문할 때마다 `전제 질문지 진행률: N% (완료/전체)`를 표시한다.
3. 완료율은 `완료 항목 수 ÷ 전체 항목 수 × 100`으로 계산하고 소수점 이하는 버린다.
4. 사용자가 의미를 명확하게 답한 항목만 완료로 계산한다. 후속 확인이 필요한 항목은 완료로 계산하지 않는다.
5. 새로운 필수 전제가 발견되면 전체 항목 수와 완료율을 갱신하고 변경 이유를 알린다.
6. 한 번에 소수의 핵심 질문만 제시한다.
7. 질문지가 100%가 된 뒤에도 사용자가 승인한 `확정` 내용만 기준 문서에 반영한다.

## 병렬 세션 작업과 용어 관리

- 병렬 작업을 시작하기 전에 각 세션의 담당 브랜치, 수정 허용 파일, 규칙 원본과 병합 담당 세션을 정한다.
- 각 세션은 자기 브랜치의 `docs/game-design/terminology.md`에 신규·변경 용어의 공식 용어, 쉬운 뜻, Dino TD에서의 정의, 실제 게임 예시와 사용하지 않을 표현을 직접 작성한다.
- 용어를 추가하거나 변경한 세션은 용어집 하단의 임시 `용어 병합 메모`에 세션과 브랜치, 변경 이유, 영향 문서와 기존 용어와의 충돌 가능성을 기록한다.
- 세션 종료 시 변경 파일, `확정`·`가정`·`미정`·`검증 필요`, 신규·변경 용어, 관련 문서 영향과 병합 주의점을 인계한다.
- 병합은 대상 세션의 작업이 모두 커밋됐고 작업 폴더가 깨끗하며, 담당 범위 밖 변경과 병합 표시가 없고, 신규·변경 용어가 있다면 용어 병합 메모가 작성된 경우에만 시작한다.
- 병합 담당 세션은 용어 중복과 표현 차이를 점검한다. 실질적인 충돌은 임의로 확정하거나 수정하지 않고 사용자에게 보고한다.
- 문제가 없는 용어는 공식 형식으로 통합하고 관련 임시 용어 병합 메모를 삭제한다.

세션 인계는 다음 순서와 제목을 사용한다.

```md
## 세션 인계

- 담당 세션과 브랜치:
- 변경 파일:
- 확정:
- 가정:
- 미정:
- 검증 필요:
- 신규·변경 용어:
- 관련 문서 영향:
- 병합 주의점:
```

## 병합 후 전체 Markdown 점검

병합 담당 세션은 병합이 완료된 뒤 프로젝트의 모든 Markdown 파일을 처음부터 끝까지 다시 읽고 다음 항목을 각각 점검한다.

1. 규칙 원본의 소유권 중복
2. 동일 수치의 불일치
3. 공식 용어와 사용하지 않을 표현의 혼용
4. 해금, 전투와 카드 등 진행 순서의 모순
5. 규칙 사이의 직접 충돌

- 각 항목은 반드시 `문제 없음` 또는 구체적인 문제 목록으로 보고한다.
- 문제에는 관련 파일, 근거 문장, 영향과 추천 수정안을 포함한다.
- 발견한 문제는 사용자 승인 전까지 수정하지 않는다.
- 다섯 항목의 결과가 모두 기록되고 문제가 없는 임시 용어 병합 메모가 정리되어야 병합 점검을 완료한 것으로 본다.

## 완료 보고

- 변경한 파일을 나열한다.
- 반영한 확정 사항과 남은 미정·검증 필요 사항을 구분한다.
- 기획 작업이면 사용한 가정도 구분한다.
- 다른 세션의 변경을 발견해 수정하지 않은 파일이 있으면 함께 알린다.
