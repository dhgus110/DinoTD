# Dino TD 작업 시작 규칙

## 목적

- 모든 작업에서 기존 결정, 공식 용어와 문서 작성 원칙을 빠뜨리지 않는다.
- 두 개 이상의 Codex 세션이 함께 작업할 때 기존 변경을 덮어쓰거나 같은 파일을 동시에 수정하는 충돌을 방지한다.

## 매 작업 시작 전 필수 절차

1. 프로젝트 루트가 `C:\Users\jeong\Desktop\DinoTD`인지 확인한다.
2. `git status --short`로 다른 세션이나 사용자가 만든 변경사항을 확인한다.
3. `rg --files --hidden -g '*.md' -g '!.git/**'`로 숨김 폴더를 포함한 프로젝트 루트 아래의 모든 Markdown 파일을 찾는다.
4. 검색된 Markdown 파일을 예외 없이 처음부터 끝까지 모두 읽는다.
5. 긴 문서의 출력이 잘리면 나누어 읽어 마지막 줄까지 확인한다.
6. 읽은 문서에서 현재 작업과 관련된 확정 규칙, 공식 용어, 미정 사항과 검증 필요 사항을 구분한다.
7. 기획 또는 용어 작업이면 `docs/guidelines/DESIGNER_GUIDE.md`의 담당 절차와 품질 기준을 적용한다.
8. 문서 사이에 충돌이 있으면 `AGENTS.md`에 정의된 지침 우선순위를 확인하고, 그래도 해결되지 않으면 임의로 한쪽을 선택하지 말고 충돌 위치와 선택지를 사용자에게 알린다.
9. 다른 세션이 변경 중인 것으로 보이는 파일은 덮어쓰지 않는다. 같은 파일을 수정해야 한다면 먼저 사용자와 작업 소유 범위를 정한다.
10. 위 절차가 끝난 뒤에만 분석, 기획 제안, 파일 작성 또는 구현을 시작한다.

## 읽기 범위

- 루트의 `AGENTS.md`와 그 밖의 모든 Markdown 파일
- `.rules` 안의 모든 Markdown 파일
- `docs` 아래의 기획서, 세부 규칙, 용어집과 작성 지침
- 이후 새로 추가되는 모든 Markdown 파일
- Git에 아직 추가되지 않은 Markdown 파일도 읽기 대상에 포함한다.

## 작업 중 재확인

- 작업 도중 다른 세션의 변경이 감지되면 변경된 Markdown 파일을 다시 읽는다.
- 문서를 수정하기 직전에 해당 문서의 최신 내용과 `git status --short`를 다시 확인한다.
- 새 용어나 규칙을 추가할 때는 `docs/game-design/terminology.md`와 관련 규칙의 단일 원본을 먼저 확인한다.

## 완료 보고

- 변경한 파일을 나열한다.
- 반영한 확정 사항과 남은 미정·검증 필요 사항을 구분한다.
- 다른 세션의 변경을 발견해 수정하지 않은 파일이 있으면 함께 알린다.
